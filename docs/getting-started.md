# Быстрый старт

[Документация](README.md) · [Обзор](project-overview.md) · [Эксплуатация](operations.md) · [Тезаурус](glossary.md)

Этот маршрут позволяет проверить приложение, harness и агента по отдельности. Выполняйте команды из корня репозитория.

## 1. Подготовить среду

Требуются Git, `rg` (ripgrep), Node.js 24.15 или новее и npm. Репозиторий фиксирует рекомендуемую ветку Node в `.nvmrc`.

```bash
nvm use
npm ci
```

`npm ci` устанавливает ровно те версии, которые записаны в `package-lock.json`. Это важно для воспроизводимости: модель и человек должны проверять изменения в одинаковом окружении.

## 2. Запустить blank-приложение

```bash
npm start
```

Angular dev server откроет приложение на `http://localhost:4200`. Это обычное web-представление Ionic-приложения; нативные проекты для Android и iOS пока не нужны.

## 3. Проверить базовый проект

```bash
npm run verify
```

Общий pipeline проверяет форматирование, production build, unit-тесты, конфигурацию Capacitor, маршрутизацию skills, исходную конфигурацию агента и тесты его policy/runtime.

## 4. Подключить модель

Создайте локальный конфигурационный файл из примера:

```bash
cp .env.local-ai.example .env.local-ai
```

Минимальная конфигурация выглядит так:

```dotenv
LOCAL_AI_BASE_URL=https://model.example.com/v1
LOCAL_AI_MODEL=gpt-oss-20b
LOCAL_AI_API_KEY=<token-if-required>
```

Файл `.env.local-ai` игнорируется Git. Не добавляйте реальные адреса приватной инфраструктуры, имена пользователей и токены в документацию или коммиты. Варианты подключения описаны в [`ai/remote-model.md`](../ai/remote-model.md), а production-контур — в [deployment и hardening](deployment-and-hardening.md).

Проверьте конфигурацию:

```bash
npm run ai:doctor
npm run ai:smoke
```

`ai:doctor` проверяет локальные prerequisites и skills. `ai:smoke` обращается к endpoint, запрашивает список моделей и делает минимальную проверку ответа.

## 5. Увидеть, какой контекст получит модель

```bash
npm run ai:context -- --query "Angular signals и HttpClient"
npm run ai:context -- --query "Камера и разрешения в Capacitor"
```

Эти команды **не обращаются к модели**. Они показывают:

- токены, выделенные из задачи;
- skill manifests, которые всегда присутствуют;
- выбранные reference-фрагменты;
- оценку релевантности;
- объём итогового контекста.

Именно с этой команды удобно начинать отладку, если ответ модели не учитывает нужную технологию. Подробнее: [извлечение контекста](harness/context-retrieval.md).

## 6. Задать read-only вопрос

```bash
npm run ai:ask -- "Спроектируй offline-aware поток данных для Ionic Angular"
```

Команда собирает trusted skill context, добавляет системные правила и отправляет запрос модели. Она печатает ответ, но не даёт модели инструментов для изменения файлов.

Если код blank-проекта нужен как пример, включите его явно:

```bash
npm run ai:ask -- --with-project-reference "Адаптируй существующую home page"
```

Файлы проекта будут помечены как untrusted reference. Они могут содержать полезные примеры, но не могут переопределять системные инструкции.

## 7. Выполнить агентную задачу

Сначала проверьте доступность изоляции:

```bash
npm run agent:docker:build
npm run agent:doctor
```

Затем поставьте небольшую задачу:

```bash
npm run agent -- "Добавь доступное пустое состояние на домашнюю страницу"
```

Требование: основная рабочая копия Git должна быть чистой. Агент создаст отдельный worktree, оставит изменения там и напечатает путь для ревью.

После проверки можно либо перенести изменения вручную, либо запустить новую задачу с автоматическим применением успешного патча:

```bash
npm run agent -- "Добавь доступное пустое состояние" --apply
```

`--apply` не отменяет проверок и не расширяет права на запись. Для защищённого файла run остановится и напечатает идентификаторы:

```bash
npm run agent -- "Обнови конфигурацию Capacitor"
npm run agent:status -- <run-id>
npm run agent:approve -- <approval-id>
npm run agent:resume -- <run-id>
```

Approval действует только для точного patch и данного run. Секреты, `.git`, `.agent`, ключи подписи и другие denied paths остаются недоступны. Подробности: [executors, approvals и Agent API](agent/executors-approvals-api.md).

## 8. Добавить нативную платформу

Только когда приложение действительно должно собираться под выбранную платформу:

```bash
npx cap add android
npx cap add ios
npm run cap:sync
```

Не запускайте Gradle, CocoaPods или Xcode для web-only изменений. Правила выбора плагинов и платформенных адаптеров описаны в [архитектуре](architecture.md#уровень-гибридного-приложения).
